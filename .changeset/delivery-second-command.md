Delivery is a second command over the Run Branch, not loop behaviour (ADR 0048): `readyrun deliver --mode <name> --branch <run-branch>` renders a settled Run Branch into published state on the forge, and report-only stays the default until you run it. Built-ins: `family-pr` (a completed family as one pull request titled after the parent, refusing interleaved or unintegrated ranges by name), `stack` (one branch and pull request per Ticket, each based on the previous), and `main` (fast-forward the default branch, refusing while the checkout stands on it). Deliver gets its own Doctor and its own read-only Plan (`deliver --preview`: what would be pushed, which PRs opened, on which bases) and reconciles rather than performs — artifacts are keyed by head-branch names derived from Tracker identity (`readyrun/deliver/<id>`), so a retried delivery finishes its own half-done work and never opens anything twice. `--draft` and `--label` are birth options, applied once. A public `createDelivery` seam joins the API, sibling to `createTrackerAdapter`; config may register strategies under `deliveries`, and which mode runs is the flag's, never config's. Forge access rides the environment's existing git and `gh` credentials; a forgeless Tracker such as Linear refuses the pull-request modes by name while `main` works everywhere. Tracker Adapters answer two new read-only facts: `inspect().forge` (the forge a Tracker is backed by, when it is one) and `tickets(ids)` (Tickets by id, including ones that left the Frontier — the facts delivery keys its artifacts on). The Launcher's first question names what to assemble — a Run or a Delivery — and when a family's Tickets have all landed, the Run's completion report names the `deliver` command the same way a cap stop names the continue command; it never runs it.
