The GitHub Tracker Adapter stands on one Tracker Adapter floor: its `frontier`, `waiting`, and `tree` are thin partitions over a single rooted candidates read, so root precedence (the explicit list bypasses the selector but never `ready: "unblocked"`; the parent narrows the selector and is never worked itself) and pick order (issue number ascending) are written once. A root naming one Ticket twice is now refused as a lie instead of silently answered, the blocking-expression schema probe is read once per process instead of once per call, pagination and the GraphQL transport (one error shape: auth, unreachable, or the vendor's own words) are shared, ready for the next Tracker Adapter to stand on the same floor.
