# @readyrun/readyrun

## 0.3.0

### Minor Changes

- [#198](https://github.com/MichaelBuss/readyrun/pull/198) [`ed83e2e`](https://github.com/MichaelBuss/readyrun/commit/ed83e2efe00f8f399dc030c52af4cdc3d09058c7) Thanks [@MichaelBuss](https://github.com/MichaelBuss)! - A Run's base is probed against origin once at start: one read-only `git ls-remote origin <default-branch>` — no fetch, no ref mutation — joins Doctor's check family, and the verdict rides the resolved base wherever it renders (Run start, `doctor`, and the Plan's preview, ADR 0046). Stale means containment: the base does not contain origin's tip of the default branch. Fresh and ahead are silent, the behind-count is best-effort naming (rendered only when the tip's objects are local, the two SHAs otherwise), and every probe failure — network down, credentials rejected, an empty answer — warns, names why, and lets the Run proceed; no `origin` remote and a detached HEAD skip silently. Warn versus gate is keyed on who named the base: a base nobody named — HEAD standing stale on the default branch — refuses the Run and `doctor`, naming `--allow-stale-base` as the escape, which downgrades the refusal to the warning a base named by `--base` gets; the flag does not skip the probe. This is the single carve-out from disclosure-not-a-gate ([#186](https://github.com/MichaelBuss/readyrun/issues/186)).

- [#195](https://github.com/MichaelBuss/readyrun/pull/195) [`c0f746a`](https://github.com/MichaelBuss/readyrun/commit/c0f746a2b1f2b1640311acbf0c248529443247a6) Thanks [@MichaelBuss](https://github.com/MichaelBuss)! - One argv grammar serves all four Worker Adapters: `custom()` rides the same argv assembly the print-mode Adapters use — its declared `args` as the leading args, print mode suppressed, since the wrapped binary may still be able to ask — and the assembler owns the grammar's name (`assembledWorker`, `printMode` a declared fact). An unknown `{placeholder}` in declared args is refused when the Adapter is built, as a named `UnknownPlaceholderError`, instead of failing Doctor or a Run later; Doctor no longer inspects the Worker Adapter's argv shape (`staticArgv` is gone), and the spawn plumbing is no longer exported — Worker Adapter tests drive the factories ([#174](https://github.com/MichaelBuss/readyrun/issues/174)).

- [#200](https://github.com/MichaelBuss/readyrun/pull/200) [`de56921`](https://github.com/MichaelBuss/readyrun/commit/de56921dad17559ec2e134ace8101bc44f25bb76) Thanks [@MichaelBuss](https://github.com/MichaelBuss)! - Delivery is a second command over the Run Branch, not loop behaviour (ADR 0048): `readyrun deliver --mode <name> --branch <run-branch>` renders a settled Run Branch into published state on the forge, and report-only stays the default until you run it. Built-ins: `family-pr` (a completed family as one pull request titled after the parent, refusing interleaved or unintegrated ranges by name), `stack` (one branch and pull request per Ticket, each based on the previous), and `main` (fast-forward the default branch, refusing while the checkout stands on it). Deliver gets its own Doctor and its own read-only Plan (`deliver --preview`: what would be pushed, which PRs opened, on which bases) and reconciles rather than performs — artifacts are keyed by head-branch names derived from Tracker identity (`readyrun/deliver/<id>`), so a retried delivery finishes its own half-done work and never opens anything twice. `--draft` and `--label` are birth options, applied once. A public `createDelivery` seam joins the API, sibling to `createTrackerAdapter`; config may register strategies under `deliveries`, and which mode runs is the flag's, never config's. Forge access rides the environment's existing git and `gh` credentials; a forgeless Tracker such as Linear refuses the pull-request modes by name while `main` works everywhere. Tracker Adapters answer two new read-only facts: `inspect().forge` (the forge a Tracker is backed by, when it is one) and `tickets(ids)` (Tickets by id, including ones that left the Frontier — the facts delivery keys its artifacts on). The Launcher's first question names what to assemble — a Run or a Delivery — and when a family's Tickets have all landed, the Run's completion report names the `deliver` command the same way a cap stop names the continue command; it never runs it.

- [#187](https://github.com/MichaelBuss/readyrun/pull/187) [`140d1b0`](https://github.com/MichaelBuss/readyrun/commit/140d1b04da5437c4dab98c06c883915ce1503a9e) Thanks [@MichaelBuss](https://github.com/MichaelBuss)! - The Worker Adapter seam answers the one Effort question beside its type: `mapsEffort` — does this Adapter map Effort (a flag plus a declared vocabulary) — and `declaredEffortVocabulary` — the values it declares (ADR 0042). Doctor's gate is unchanged, the Launcher's Effort question skips and offers by the predicate, and Init reads the declared constants instead of building throwaway Adapters to inspect them.

- [#190](https://github.com/MichaelBuss/readyrun/pull/190) [`173cca6`](https://github.com/MichaelBuss/readyrun/commit/173cca61c7bd384fd8ec156be4985fa480e48af2) Thanks [@MichaelBuss](https://github.com/MichaelBuss)! - Linear's suggested Branch name travels on the answer instead of in the Adapter: the Linear Tracker Adapter maps Linear's own `branchName` onto each **Ticket**'s new optional `suggestedBranch`, so `frontier`, `waiting`, and `tree` hand the caller the suggestion with the **Ticket** it belongs to (ADR 0004, [#167](https://github.com/MichaelBuss/readyrun/issues/167)), and `branchName` — now derived once in the **Tracker Adapter** defaults — reads the **Ticket** it is handed rather than a map only a prior `frontier` read could have seeded. Behaviour on a **Run** is unchanged: a Linear **Ticket** with a suggestion still works the suggested name, and one without still gets `readyrun/<id>`.

- [#189](https://github.com/MichaelBuss/readyrun/pull/189) [`8805dce`](https://github.com/MichaelBuss/readyrun/commit/8805dce0052c46b5b1f2b14e4fb5be380965955e) Thanks [@MichaelBuss](https://github.com/MichaelBuss)! - The Linear Tracker Adapter stands on the same Tracker Adapter floor as GitHub: its `frontier`, `waiting`, and `tree` are thin partitions over one rooted candidates read, so root precedence (the explicit list bypasses the selector but never `ready: "unblocked"`; the parent narrows the selector and is never worked itself) and pick order (identifier ascending) are written once, and pagination, the GraphQL transport, and the blocking-expression schema probe are shared instead of copied. One truth comes with the floor: a Ticket that has left the Frontier is not an open candidate, so a Linear state selector naming a finished Ticket's state no longer picks it.

- [#196](https://github.com/MichaelBuss/readyrun/pull/196) [`d0f6c8e`](https://github.com/MichaelBuss/readyrun/commit/d0f6c8e3ffa181c6b3b7d2c1dac4d92856f774a8) Thanks [@MichaelBuss](https://github.com/MichaelBuss)! - The Run consumes the Plan. `run()` resolves the Plan — Doctor's verdict, the
  Frontier in pick order, the base, the Run Branch, the cap, and the Workers'
  Effort and Permissions — and its loop (`runPlan`, exported alongside) reads
  every fact from that Plan: no first-iteration re-derivation of Doctor's rules,
  the Plan's Frontier snapshot is the first pick, and the Run collects onto the
  Run Branch the Plan named ("named when the Plan is computed"). The loop
  re-verifies only what can change mid-loop: the cwd-fidelity probe at start,
  and a fresh Frontier read every iteration after the first, which still lets
  waiting Tickets join when their blockers clear. The Plan module owns its input
  shape (`PlanInput`; `RunOptions` is now its alias), closing the import cycle
  with the Run module, and a Launcher→Run session reads the Tracker once per
  fact — the Run adds no start reads, asserted by fixture call counts. A refusal
  in the rendered Plan is refused by the Run without re-reading the Tracker.

- [#182](https://github.com/MichaelBuss/readyrun/pull/182) [`8bbf882`](https://github.com/MichaelBuss/readyrun/commit/8bbf88277dd6299d8abdfd46ad2f2b1e943096a1) Thanks [@MichaelBuss](https://github.com/MichaelBuss)! - The GitHub Tracker Adapter stands on one Tracker Adapter floor: its `frontier`, `waiting`, and `tree` are thin partitions over a single rooted candidates read, so root precedence (the explicit list bypasses the selector but never `ready: "unblocked"`; the parent narrows the selector and is never worked itself) and pick order (issue number ascending) are written once. A root naming one Ticket twice is now refused as a lie instead of silently answered, the blocking-expression schema probe is read once per process instead of once per call, pagination and the GraphQL transport (one error shape: auth, unreachable, or the vendor's own words) are shared, ready for the next Tracker Adapter to stand on the same floor.

- [#191](https://github.com/MichaelBuss/readyrun/pull/191) [`24a8da5`](https://github.com/MichaelBuss/readyrun/commit/24a8da56d3296e667548781ee2f275d487edcca3) Thanks [@MichaelBuss](https://github.com/MichaelBuss)! - Each Worker Adapter answers the model question at the seam: `listModels` on the Adapter — Cursor its `--list-models` listing with the static fallback catalog, Claude its static catalog, opencode its `models` command in the bare-id grammar — read through `listedModels(adapter)`, with `ListedModel` now a public type; the typed fallback prompt's placeholder is the Adapter's too (`typedModelPlaceholder`, opencode's `provider/model`). Init asks the seam instead of owning vendor binary names and output parsers, so a vendor rename or a listing-output change touches exactly one module; the select/autocomplete flows and the typed fallback prompt behave as before (ADR 0047).

### Patch Changes

- [#193](https://github.com/MichaelBuss/readyrun/pull/193) [`7abe3ef`](https://github.com/MichaelBuss/readyrun/commit/7abe3ef0d51e831749e244c5dd2d61110e90d0a0) Thanks [@MichaelBuss](https://github.com/MichaelBuss)! - One call collects a finished Ticket: `collectTicket` on the git module removes the Worktree, merges the Ticket's Branch into the Run Branch as exactly one merge commit, deletes the Ticket's Branch, and returns the Landing — the remove-before-merge ordering now lives inside the module, and the Run loop assembles nothing. A Worktree that cannot be removed is reported as its own hard stop ("ReadyRun could not remove the Worktree at …") instead of a raw git error, and a merge failure no longer claims a kept Worktree the collect already removed. Run Branch membership, first-parent merge shape, and base-tip rules are unchanged (ADR 0028 / 0033 / 0034).

- [#194](https://github.com/MichaelBuss/readyrun/pull/194) [`2228445`](https://github.com/MichaelBuss/readyrun/commit/222844588deae906bdf43e9d9e756c3ba77be51e) Thanks [@MichaelBuss](https://github.com/MichaelBuss)! - Doctor's check and the Plan share one rooted-Frontier read: a rooted `readyrun doctor` (or `run --preview`) fetches the Frontier once instead of twice in the same command, and Doctor's verdict carries the read it made. Effort and Permissions resolve CLI-over-config with the default `ask` in one place — `resolveRunSettings` — instead of being re-derived at Doctor's verdict, the Worker spawn payload, and the Plan; `collectDoctorFailures` takes that one input instead of six positional parameters. Doctor's output and the rendered Plan are unchanged.

## 0.2.1

### Patch Changes

- [#183](https://github.com/MichaelBuss/readyrun/pull/183) [`b9c5a74`](https://github.com/MichaelBuss/readyrun/commit/b9c5a74add8b7c4443d24a8e64a411de8c592e84) Thanks [@MichaelBuss](https://github.com/MichaelBuss)! - The npm tarball ships compiled JavaScript instead of TypeScript sources: `npm run build` emits `dist/` (`*.js` + `*.d.ts`) and the npm `bin` and `exports` point at the compiled files. Node refuses to strip types for files under `node_modules`, so 0.2.0's TS-only npm artifact failed to load for every consumer — `readyrun` on PATH and `import "@readyrun/readyrun"` alike died with `ERR_UNSUPPORTED_NODE_MODULES_TYPE_STRIPPING`. JSR keeps publishing the sources, versions stay in lockstep, and a consumer's own `readyrun.config.ts` (outside `node_modules`) still loads via Node's default type stripping.
