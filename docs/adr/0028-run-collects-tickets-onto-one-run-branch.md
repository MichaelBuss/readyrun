# A Run collects its Tickets onto one Run Branch

A Run has one Run Branch, named `readyrun/run-<YYYYMMDD-HHMMSS>` by the harness rather than by a Tracker Adapter, starting from whatever the Consumer's checkout was on when the Run started and created lazily at the first successful merge so that a Run landing nothing leaves no ref behind. Each Ticket's Branch is cut from that branch's current tip, and when its Worker succeeds it is merged in with `--no-ff` and then deleted: one Ticket becomes one entry in the Run Branch's first-parent history with the Worker's own commits preserved underneath, and the next Ticket starts from a tree containing everything the Run has already finished. Leaving N unmerged Branches per Run was rejected because merging ten of them by hand is precisely the human-in-the-loop cost this product exists to delete. Cutting each Ticket's Branch from the *previous Ticket's* Branch was rejected because there is no well-defined "previous" once more than one Worker runs at a time, where a named ref stays well-defined at any concurrency — so this keeps ADR 0007's promise that concurrency is a knob and not a rewrite. A single long-lived integration branch across Runs was rejected as trading the merge burden for permanent divergence from the default branch. Squashing each Ticket to one commit was rejected because it destroys the Worker's granularity to buy readability that `--no-ff` already provides, and it would put ReadyRun back to authoring a message about code it did not write; a plain fast-forward was rejected for leaving no Ticket boundaries in the history at all. Two consequences: serial Runs cannot conflict, because each Ticket branches from the tip with nothing landing in between, so conflict handling is a cost of raising concurrency (#5) rather than of this decision; and a hard stop leaves the Run Branch exactly as it stands, since discarding the Tickets that did land because a later one failed would destroy the only thing the Run produced. ReadyRun still merges nothing into the default branch — what becomes of a Run Branch is the Consumer's, and remains #1's question.
