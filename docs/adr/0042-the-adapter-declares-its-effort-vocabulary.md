# The Adapter declares the Effort vocabulary it can honestly map

ReadyRun's `Effort` union is the transport vocabulary; the truth about which values a CLI accepts lives with the **Worker Adapter**, which declares the values it maps, so an Effort outside that declaration is a config lie **Doctor** fails and the **Launcher**'s Effort question can only offer values that exist. This amends ADR 0021: `custom()` no longer implies the standard five by passing `--effort` through blind — it must declare its vocabulary explicitly (no known Consumer config sets Effort on `custom()`, so nothing breaks today) — and `opencode()` (#120) maps `--variant`, whose true values are provider-specific, so it declares only the documented `high` | `max` until a Consumer's trial corrects the claim. The config's Effort field is typed against the chosen Adapter's declaration, making an out-of-vocabulary value a compile error before **Doctor** ever runs. A user-widened vocabulary option was rejected because it reopens "selected something that does not exist"; `opencode()` declaring nothing in v1 (the Cursor precedent) was rejected because it forfeits the typed vocabulary for no honesty gain.
