# Worker Adapters gain an optional Doctor probe, distinct from the binary check

Doctor's existence-only check on `config.worker.bin` cannot tell an installed CLI from one that is installed but not logged in — that failure previously only surfaced as a Worker spawn failure mid-Run. A Worker Adapter may now optionally define `probe(): Promise<ProbeResult>`, a cheap, read-only invocation of its own CLI; Doctor runs it — once the binary is confirmed to exist — and reports a failure message distinct from "binary missing". `cursor()` runs `agent status`; `claude()` runs `claude auth status`. Claude's CLI documents an exit code that distinguishes logged-in from not; Cursor's does not, so the probe also treats recognizable auth-failure text in the CLI's output (`not authenticated`, `not logged in`, and similar) as a failure regardless of exit code — a CLI whose status command always exits 0 must not make the probe a no-op. `custom()` gains no probe of its own — an unsupported CLI's auth state is not something the package can guess at — so it keeps today's existence-only check exactly as before. This does not make ReadyRun the owner of CLI auth (ADR 0010, spec point 64): the probe only reads status the coding CLI already exposes, it never logs in or out.
