# A stale base gates only when the Consumer did not name it

A Run's base is whatever the Consumer's checkout sat on at start, and until now nothing compared that base against origin: the disclosure names where the base is — commit, branch, the non-default callout, the dirty warning, the HEAD trap — but never whether it is fresh, so a Consumer who forgot to pull spent a whole Run of Worker tokens landing Tickets on history already behind. So one read-only probe joins the check family at Run start: `git ls-remote origin <default-branch>` — one network call, existing credentials, no fetch, no ref mutation, once at start like every other check and never per iteration. Stale means the resolved base does not contain origin's tip commit of the default branch, a containment test rather than a commit count, because `ls-remote` returns only a SHA and ReadyRun does not fetch to count; it is also sound without qualification for shallow clones, since a base that contained the tip would have the tip's objects. Fresh — base equal to tip — and ahead — base contains the tip it is ahead of — are silent, and the "N commits behind" count is best-effort naming rendered only when the tip's objects happen to be local, the message otherwise naming the two SHAs. The verdict speaks only where freshness is a meaningful question: a base nominally the default branch, meaning HEAD standing on it with no `--base`, or `--base` naming the default branch itself. A feature branch, any other commit-ish, and a continuation Run's `--base readyrun/run-<stamp>` get no verdict — the existing non-default-base callout already discloses those, and freshness against the default branch's tip is not the question they answer. The default branch is resolved the way the disclosure already resolves it — the `origin/HEAD` symbolic-ref falling back to `init.defaultBranch` — not by asking the remote what its default is.

Warn versus gate is keyed on who named the base. With no `--base` the Consumer implicitly meant HEAD, and a stale HEAD on the default branch is closer to a lie than a choice: that one case gates, the Run and `doctor` refusing and naming `--allow-stale-base` as the escape, which downgrades the gate to the same warning a named base gets — the gap is still disclosed; the flag does not skip the probe. A base named by `--base` was chosen on purpose and is warned, never gated. This is the single carve-out from ADR 0039's disclosure-not-a-gate line, and starting from a feature branch on purpose remains legitimate and stops nothing.

Every probe failure degrades to a warning, never a failure: network down, credentials rejected, or an empty answer — the remote holds no ref matching the locally resolved default branch, as when the fallback guesses wrong on a never-fetched clone — each warn, name why, and let the Run proceed, because offline must not block a Run and Doctor fails lies, not outages (the #113 family). A checkout with no `origin` remote skips silently, there being nothing to compare against, and a detached HEAD gets no verdict, detaching being a deliberate act the disclosure already names — the same family as a feature branch.

The verdict is computed once during base resolution as part of the Plan (ADR 0039); the gate lives in Doctor, the only rule-keeper, so `run`, `doctor`, and `run --preview` all carry it, and the preview's probe is exactly why ADR 0039's preview skip does not extend here — that skip belongs to the Worker-spawning fidelity probe, where this is one read-only call mutating nothing. The warning renders wherever the base renders, so Run start, Doctor, and the preview say the same words. The probe vouches for Run starts only: once at start, never mid-Run, where the Run Branch is local and origin-irrelevant (ADR 0033), and a continuation Run is a new Run whose explicit `--base` lands in the warned path (ADR 0034).

Warn-only everywhere was rejected because the forget case — no `--base`, stale default branch — is precisely the Consumer who will not read a warning before walking away, and the disclosure would keep narrating a Run it watched walk into stale history. Fetch-and-compare was rejected because counting the gap exactly requires the remote's objects and fetching mutates remote-tracking refs; ReadyRun leaves the checkout where the Consumer left it. Asking the remote which branch is its default was rejected as an extra round-trip duplicating a resolution the disclosure already shares. A config knob for the escape was rejected because the Consumer who forgot to pull is also the one who never set config. Hard-failing on an unreachable probe was rejected as a network check pretending to be a Frontier lie.

## Consequences

- The base disclosure's "disclosure, not a gate" narrows by exactly one case. Consumers scripting Runs against a deliberately stale default branch pass `--allow-stale-base`.
- Doctor now makes one network call. Accepted: read-only, credentialed like every Tracker call, once at start.
- An environment where `ls-remote` cannot pass warns on every Run. Accepted: the warning names why, and the Run still starts.
- Shallow clones need no special case; the containment reading of a missing tip object is true about the DAG, not the local object store.
