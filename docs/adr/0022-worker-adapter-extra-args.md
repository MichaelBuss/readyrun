# cursor() and claude() take extraArgs, not a growing options bag

`cursor()` and `claude()` each accept an optional `extraArgs: string[]`, a static list of flags spawned between `-p` and `--model`. This is the same slot `custom()`'s own `args` already occupies relative to `--model`, so a Consumer who later drops from `claude()` to `custom()` (or back) does not have to relearn where a flag goes. A named option per vendor flag (e.g. `verbose: boolean`) was rejected — it grows the config surface once per CLI flag ReadyRun does not otherwise care about, and it duplicates what `custom()` already solved generically. `extraArgs` is unknown-key-checked like every other adapter option, and it composes with `effort`: effort still resolves through the Run's `effort` config default rather than `extraArgs`, since that value is validated by Doctor per adapter (ADR 0021). `custom()`'s `args` are untouched.
