# A blocker's missing merge marker is a Run-start disclosure, never a gate

#70 is the decision ADR 0049 deferred: a **Ticket** the **Tracker** reports unblocked can reach the **Frontier** of a **Run** whose resolved base does not contain the blocker's work, because unblocked is the **Frontier** transition (ADR 0006, ADR 0016) and a **Run**'s base is whatever was resolved for it (ADR 0034) — so across **Runs** a successor **Worker** can start without the dependency its blocker's **Landing** was supposed to provide. Within a **Run** the gap is already closed: each **Branch** is cut from the **Run Branch**'s tip (ADR 0028), so a picked successor's tree contains every **Ticket** the **Run** has finished. The decision here is two-sided. `unblocked` keeps meaning the **Tracker**'s **Frontier** transition — ReadyRun does not own integration (ADR 0028, ADR 0033), a blocker's **Run** may end unmerged for weeks by the **Consumer**'s choice, and the shared contract that makes a successor eligible again on `leaveFrontier` is answered by **Trackers** that hold no git at all, so merge-waiting semantics would not refine the query but change the product: nothing merges to the default branch mid-**Run**, so a family of dependent **Tickets** could then only be run one **Run** per **Ticket** with an integration in between — the hand-merge cost ADR 0028 exists to delete. And the deferred detection ships — as a best-effort, warning-only disclosure computed with the **Plan** (ADR 0039) and rendered wherever the **Plan** renders: **Run** start, `run --preview`, and **Doctor**. When a **Frontier** **Ticket** is unblocked and a blocker that has left the **Frontier** has no `Ticket <id>:` merge marker reachable from the resolved base's first-parent history, the **Plan** says so in marker terms — the **Tracker** says unblocked; the base does not contain the marker — and names the common ways a real landing can look the same.

The check can only ever speak about markers, and this ADR names that as a ceiling, not a defect to be fixed later. The merge message is the one deterministic marker ReadyRun leaves, and integration preserves it unevenly — read off the shipped **Delivery** strategies rather than assumed: `main` fast-forwards the default branch to the **Run Branch**, so every marker arrives verbatim; a `stack` part merges under a forge-generated subject (`Merge pull request #N…`) with the per-**Ticket** title carried only in the body, and a **Consumer** can edit a squash message; `family-pr` publishes each child's marker only in the PR body and titles the merge after the parent; a hand squash and a human-implemented blocker leave no marker at all. So the walk reads first-parent subjects — the same history and the same `Ticket <id>:` grammar delivery's merge parser reads, one reader of one history as ADR 0049 asked — and the wording never says "work missing", because that is the one claim the base cannot support. The converse does hold, and it is what makes the disclosure safe to trust: first-parent is what excludes **Worker**-authored commits, which ride under a merge's second parent, so a first-parent `Ticket <id>:` subject on the base is the **Run**'s own merge or an integration that carried it intact — a marker found is work found; a marker absent is a question, not an answer.

A gate was rejected because the evidence it would stop a **Run** on is evidence the **Consumer** may be unable to clear — every markerless landing above — which is #70's own warning that the pain moves rather than goes; ADR 0046's carve-out logic finds no purchase here, because that gate fires on the base the **Consumer** did not choose, and a missing marker is not a lie about the **Frontier** (ADR 0009) for **Doctor** to fail. Pick-time pass-over is rejected outright: ADR 0013 refuses the word, and ADR 0049 already called the pass-over a different thing wearing it — this ADR closes that deferral by declining it. Detected and disclosed, never skipped, never gated, never silent about what it detected; where the walk cannot answer, it stays silent, git's own failure being the **Run**'s next stop, and the good case is silent the way the freshness probe's fresh-and-ahead is (ADR 0046). The "blocked on code" versus "blocked on sequencing" distinction is real and lives here — in the disclosure's wording, not in a second blocking vocabulary: the **Tracker** owns the blocking relation (ADR 0016), and a ReadyRun-owned second kind of blocked would be one more lie surface to police (ADR 0009) and one more knob for the **Launcher** to collect.

The check runs once at start like every check (ADR 0009), never mid-**Run** — the **Run Branch** is local and origin-irrelevant once picks begin (ADR 0033), and every pick already sees its blockers' work in the tree its **Branch** was cut from. It needs, per **Frontier** **Ticket**, the blockers that have left the **Frontier** — facts both shipped **Tracker Adapters** already compute internally and today drop, widened onto the answer the way ADR 0039 widened `blockedBy` for waiting **Tickets**; the contract gains them without git, which the in-memory **Tracker** proves the blocking facts never needed. Best-effort is named as best-effort in the rendering, the ADR 0046 rhyme: tell, don't touch.

## Consequences

- **Run** start, `run --preview`, and **Doctor** render the same marker disclosure; it is a **Plan** fact, computed once, never per iteration.
- Both shipped **Tracker Adapters** widen their answer with the blockers that have left the **Frontier**; free before 1.0, breaking after.
- **Consumers** integrating through markerless paths — PR-merge subjects, family PRs, hand squashes, human-implemented blockers — read the warning whenever a successor follows such a blocker. Accepted: the warning states a marker fact and its own blindness; that is the honest ceiling.
- No gate, no escape flag, no pick change; `unblocked`, the shared contract test, and ADR 0016 stand untouched.
- ADR 0049's deferral line is closed by this ADR; the narrowing note on 0049 points here.
