# Init writes unattended permissions and a CONTEXT.md contextFile

The stub Init wrote named tracker, worker, model and effort only, so `defineConfig` defaulted `permissions` to ask and the Worker got no repo language. Both blanks cost a Consumer an afternoon: print-mode cannot surface an install approval (ADR 0027), and a Worker with no glossary asks scope questions the repo's own `CONTEXT.md` already answers. Init now writes `permissions: "unattended"` into every stub, and adds `contextFile: "CONTEXT.md"` when that file is already at the Consumer root, omitting the key when it is not.

Neither is a Clack question. Permissions has one valid answer for `cursor()` and `claude()`, the adapters Init offers by default, and a Consumer on `custom()` who genuinely wants ask can change the line; asking would be a prompt whose wrong answer Doctor immediately rejects. An attended mode that is not print-mode would be the thing that earns the question, and v0 has none. `contextFile` takes the same "the file is either there or it is not" shape as Init's `.gitignore` step (ADR 0026): no prompt, no file created on the Consumer's behalf, and no guess at other filenames — a Consumer whose context lives in `AGENTS.md` or `prompt.md` edits one line. `--answers` goes through the same writer, so a stub written without a TTY carries both (ADR 0019).
