# A Run names its Frontier's root on the command line

ADR 0016's reserved root becomes a Run-time flag, not a config edit: `--ticket <id-or-url>` (repeatable) names an explicit list, `--root <parent>` names a family; the two are mutually exclusive, and a CLI root replaces any config-level root for that Run, as `--max` and `--model` already do. The list bypasses the Consumer selector but never `ready: "unblocked"`; the parent narrows the selector's Frontier to its children and is itself never worked. Naming is not sequencing: pick order stays the Tracker Adapter's stable order (ADR 0017), and a blocking relationship is the only sequencing lever — a named Ticket blocked at start is waiting work (warned, joining mid-Run when its blocker clears), so a parent whose children are all merely blocked warns and stops clean, and only permanent lies refuse to start: nonexistent, closed, duplicate, outside the root, or a root for a Tracker Adapter that cannot read parents. The cap resolves `--max`, then config, then the list's length, so a single-Ticket invocation is a Run with cap 1. The root reaches the Adapter as an optional argument on `frontier()` rather than post-hoc filtering, because blockedness is computed selector-dependently and a bypassed selector must not judge its own blockers; an Adapter's rooted answer is verified to lie within the root, so an Adapter that silently ignores a root is caught and refused. CLI-order picking, an order setting, and AI-ordered picks were all rejected: a Consumer dumps a list and the Tracker sequences it — blocking is the lever, and guessed dependencies would put a Worker on a Ticket whose foundations have not landed. Doctor takes the same root flags, so a rooted lie-check can be pre-flighted without starting a Run.
