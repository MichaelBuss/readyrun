# A Run renders the Worker's output; the Worker does not inherit the terminal

A Worker used to spawn with inherited stdio, which made a Run's screen the vendor CLI's raw transcript — untrackable for a human — and forced liveness to go silent during a Worker (ADR 0032's constraint). Now a Run pipes the Worker's stdout/stderr and renders everything printed: tool calls become one annotated line each (kind glyph + verb + target), tool results stay silent unless failed, assistant narration passes through, and unknown output is never silently dropped. Kinds come from each vendor's structured print-mode stream where the Worker Adapter owns one (Claude, Cursor) and from `custom()`'s optional `format` (e.g. `"opencode"`) otherwise; an unformatted `custom()` streams raw between the Run's lines. One glyph taxonomy covers both the Worker's activity and the Run's own lines (picked, landed, stopped, warned). On a TTY the ADR 0032 heartbeat returns between prints (glyph + elapsed since the Ticket started) — that ADR's rejection of an in-place spinner rested on the inherited terminal this ADR removes — and `--verbose` keeps today's raw passthrough one flag away; off a TTY the render is plain newline lines (ADR 0032's doctrine otherwise unchanged). Heuristic text classification was rejected as fragile against vendor cosmetic drift; documented vendor event streams are the seam. Transcript recording (#122) hooks this same event seam later.
