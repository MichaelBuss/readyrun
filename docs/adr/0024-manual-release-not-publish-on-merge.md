# Publishing is a manual release, not automatic on merge to main

CI no longer publishes to JSR on every push to `main`, and PRs are no longer blocked from merging just because `jsr.json`'s version was not bumped. The old flow bumped the version once per PR and published on merge, which meant one JSR version per PR even when several small PRs landed the same day. A `workflow_dispatch` `release` job now does the whole release on demand: pick a bump kind (patch/minor/major) from the Actions UI, and it runs the test suite, bumps `package.json`/`package-lock.json`/`jsr.json` with the existing `scripts/bump.ts`, commits and tags that bump, pushes both, then runs `jsr publish`. The PR-time `publish-preview` job still runs `scripts/publish-preview.ts` and comments on the PR, but purely informationally now (no `ok` gate, no failing check) — it tells a reviewer whether this PR's published-file changes are new or already shipped, not whether merging will publish.
