# The Launcher names the Root by rendering the Tree

The v1 Launcher assembles a **Run** but never names a **Root** — it is hardcoded rootless — while the **Tree** surface already answers one read-only look (ADR 0039), so v2 makes the Launcher's first question the tree: with no **Root** named, the selector's candidates render immediately as a forest grouped by each **Ticket**'s parent and split into the pickable-now and waiting halves, with a *"go from the top"* choice taking the rootless **Frontier** in pick order and a multi-select across the one rendering emitting the explicit `--ticket` list. Rejected: walk-the-tree drill-down (re-calling `tree()` per subtree multiplies scans and contradicts the one-look **Tree**), and asking for a parent before showing anything (the candidate forest is what the maintainer sat down to see; naming a parent remains the scale lever). Blocked **Tickets** are selectable and confirmed once when the selection ends ("waits on #x — joins when it clears"): refusing them would make the picker stricter than the flags it mirrors, so the **Launcher** would hold a rule **Doctor** doesn't, and per-pick confirms nag. The parent node is never selectable (a parent is never worked). The cap suggestion is floored at the selection's length, waiting **Tickets** included — a list capped under its own length is a slice nobody asked for, and blockers that never clear just end the **Run** early on an empty **Frontier**. The tree question goes first because the cap suggestion depends on the selection; everything after it is v1 unchanged, the **Plan** rendering the picked **Root** resolved. When an Adapter refuses `tree()`, the Launcher falls back to the same flags as text prompts (optional parent id, optional ticket ids/URLs) — a refusal narrows the rendering, never what can be assembled. No pagination: one call, one rendering, scroll.
