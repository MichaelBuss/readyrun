# createTrackerAdapter is exported as-is, not renamed to custom()

`TrackerAdapter` is brand-sealed inside `tracker-adapter.ts`; the only factory that could build one, `createTrackerAdapter`, was not part of `mod.ts`. That blocked a Consumer from wiring up a Tracker this package doesn't ship (Jira, GitLab, ...) or from mocking a Tracker without a live API call — the one place that already called it, `src/testing/`, is excluded from the JSR publish. `createTrackerAdapter` is now exported from `mod.ts` unchanged: a Consumer supplies `frontier`, `branchName`, `leaveFrontier`, `promptCopy`, and `inspect`, the same shape `github()` and `linear()` build on internally. Renaming it to `custom()` to mirror the Worker Adapter side was rejected: `mod.ts` already exports a Worker Adapter `custom({ bin, args, unattendedFlag })`, a differently-shaped factory, and a second export of the same name would collide. No new `jsr.json` export path was needed — `tracker-adapter.ts` already publishes through the top-level `.` entry once `mod.ts` re-exports it. `createTrackerAdapter` now validates its methods against the same known-keys set every other public factory uses (ADR 0009): a misspelled method name (`leaveFroniter`) is a Doctor-visible `UnknownConfigKeyError` instead of a silently-ignored typo that falls back to the no-op default.
