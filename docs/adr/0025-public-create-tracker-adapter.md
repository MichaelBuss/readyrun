# createTrackerAdapter is exported as-is, not renamed to custom()

`TrackerAdapter` is brand-sealed inside `tracker-adapter.ts`; the only factory that could build one, `createTrackerAdapter`, was not part of `mod.ts`. That blocked a Consumer from wiring up a Tracker this package doesn't ship (Jira, GitLab, ...) or from mocking a Tracker without a live API call — the one place that already called it, `src/testing/`, is excluded from the JSR publish. `createTrackerAdapter` is now exported from `mod.ts` unchanged: a Consumer supplies `frontier`, `branchName`, `leaveFrontier`, `promptCopy`, and `inspect`, the same shape `github()` and `linear()` build on internally. Renaming it to `custom()` to mirror the Worker Adapter side was rejected: `mod.ts` already exports a Worker Adapter `custom({ bin, args, unattendedFlag })`, a differently-shaped factory, and a second export of the same name would collide. No new `jsr.json` export path was needed — `tracker-adapter.ts` already publishes through the top-level `.` entry once `mod.ts` re-exports it. Unlike `custom()`, the new export does not validate its options against a known-keys set: its "options" are the adapter's own methods, not a flat config object, so the unknown-key guard (ADR 0009) does not apply the same way.
