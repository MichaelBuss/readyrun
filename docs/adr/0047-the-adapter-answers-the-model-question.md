# The Adapter answers the model question

The model facts a human setup surface needs are vendor facts, so each **Worker Adapter** answers a `listModels` question and Init asks the seam instead of owning vendor grammar (#169): Cursor's Adapter owns the `agent`/`cursor-agent` `--list-models` command, its `id - label` grammar, and the static fallback catalog; Claude's Adapter owns its static catalog, there being no listing command to ask; opencode's Adapter owns the `models` command and its bare-id grammar, answering empty when nothing can be listed honestly (#160). `listedModels(adapter)` is the one read — the empty answer when an Adapter lists none — so a vendor rename or a listing-output change touches exactly one module. The shape mirrors ADR 0042: the Effort vocabulary the Adapter declares, the model listing the Adapter answers, and the surface that asks instead of knowing. The typed fallback prompt stays Init's: it is what every empty answer lands on, and no Adapter owns the asking.
