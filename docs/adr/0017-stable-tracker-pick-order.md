# Frontier pick order is the Tracker’s stable id order

When several Tickets are on the Frontier, v0 picks in the Tracker Adapter’s stable order: GitHub issue number ascending; Linear whatever the Adapter documents so Doctor can say “X is next.” Newest-first was rejected because it would skip the oldest hole in a map. A configurable sort and a priority field on the Ticket were rejected: no current forced use, and priority would be special authoring. Doctor’s “this repo will take #52 next” is that same order.
