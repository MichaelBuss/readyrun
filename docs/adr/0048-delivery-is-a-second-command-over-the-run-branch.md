# Delivery is a second command over the Run Branch, not loop behaviour

ADR 0033's own revisit trigger has fired (#175): Consumers want finished work delivered — a completed family as one PR (#126), a stack of PRs, a fast-forward to main — without the loop growing forge powers. The decision: `readyrun deliver` is a separate command, run after a **Run** over the **Run Branch**'s settled history. The fact that makes this clean is that ADR 0028's output already is a stacked history — one merge commit per **Ticket**, each **Branch** cut from the previous tip — so delivery is a publishing policy over history that exists, never a producer of it. The **Run** never knows delivery exists; the **Run Branch** still stays local *during* the **Run**, and a **Run** still pushes nothing, which is the sense in which this narrows ADR 0033 rather than overturning it. The handoff stops being only a report the moment the **Consumer** opts into a **Delivery**. ADR 0033's CI revisit is answered: CI chains `readyrun run && readyrun deliver`. Deliver writes to the forge with the environment's existing git and `gh` credentials; nothing new is stored.

The line delivery may never cross, restated from #175: (1) **batch at the boundary** — publications happen at a **Run** end or a **Consumer** invocation, never mid-**Run**; (2) **delivery renders history, never shapes it** — no mode changes **Branch** lifetime, merge behaviour, or **Worktree** disposal; (3) **reconcile, don't perform** — deliver is an ensure keyed on **Tracker** identity, never a blind action keyed on **Run** identity; (4) **single writer per artifact** — `leaveFrontier` stays the only writer to a **Ticket**; deliver owns forge artifacts, so the "closes #N" copy (#154) lives there; **Tracker Adapters** never gain forge powers; (5) **report-only stays the default** — every publication is opt-in by running `deliver`.

Reconcile keys on deterministic artifact identity: the published artifact *is* its head-branch name, derived from **Tracker** identity — `readyrun/deliver/<parent-id>` for `family-pr`, `readyrun/deliver/<ticket-id>` per merge commit for `stack`. Existence is checked by head branch, not body search (GitHub search has indexing lag and no exact matching); a retried `deliver` after a crash finds its own half-pushed ref by name and finishes the job. Deliver owns birth, the **Consumer** owns life: `--draft` and `--label` are creation-time options applied once and never revisited — flipping draft to ready (for instance after a machine-review CI round) and all later label changes belong to the **Consumer**'s pipeline, so exists-or-not stays the only published state reconcile tracks.

The built-ins and their refusal rules. `family-pr` publishes a family's range as one PR titled after the parent when all its children have landed, and refuses with a named cause when the family's merge commits are interleaved with unrelated **Tickets** on the **Run Branch**'s first-parent history or when the commit before the family's first merge is not already in the default branch — a PR whose diff is not exactly the family's work is a lie, and contiguity plus an integrated base are what make the diff honest. Families completed across continuation **Runs** (ADR 0034) compose: the range is derived from the family **Tickets**' **Landing** facts keyed on **Tracker** identity, never from one **Run Branch**. The family PR body carries `Closes` for every child and the parent, plus the **Landing** facts. `stack` pushes one ref per merge commit, each PR based on the previous; GitHub's documented retarget-on-head-branch-delete performs the cascade for free, and mid-stack merges are the **Consumer**'s act that the next `deliver` reconciles around — it never rewrites history. The documented squash caveat (squash-merging a lower PR duplicates the upper PR's three-dot diff) surfaces as a warn-only merge-method probe in the **Delivery**'s **Plan**. `main` fast-forwards the default branch to the **Run Branch** (`git fetch . <branch>:main`), refusing when the primary checkout sits on main; unlike the PR modes it discloses rather than refuses on unintegrated bases, because it is an explicit act whose **Plan** shows exactly what would move.

The surface: `readyrun deliver --mode <name> --branch <run-branch>`, both explicit; the mode resolves to a built-in or to a strategy registered through the public `createDelivery` seam, sibling to `createTrackerAdapter` (ADR 0025); config never selects a mode. Deliver gets its own **Doctor** (remote exists, **Run Branch** and base exist, mode/forge compatibility — a forge-requiring mode on a forgeless **Tracker** such as Linear refuses with that named cause, while `main` needs no forge) and its own read-only **Plan** (what would be pushed, which PRs opened, on which bases, in what state) — the same Doctor-refuses-lies / Plan-computed-once split as `run`. The **Launcher** generalizes from assembling a **Run** to assembling a **Run** or a **Delivery**: its first question names which, decline ends a success, the **Delivery** flow collects mode and **Run Branch** (listed from the `readyrun/run-` namespace, never guessed), renders the **Plan**, and hands off to the same stdout renderer; everything it collects is flag-expressible, and `deliver` off a TTY is flags. The **Run**'s completion report may *name* the deliver command when a family completed — the same rhyme as the cap-stop naming the continue command, because it is ReadyRun's own next invocation — but never runs it.

## Consequences

- A new public seam, `createDelivery`, joins the published API; free before 1.0.
- A forge port is a new class of authority — the one ADR 0033 refused to assign to the loop — and it is held by deliver alone, on existing environment credentials.
- "No draft-vs-ready question" (ADR 0033) held only while there were no PRs; the answer is create-time choice, never tracked state.
- Linear has no forge: `family-pr` and `stack` refuse there with that named cause; `main` works everywhere.
- GitHub fact base verified 2026-10: retarget-on-head-branch-delete is documented behavior and native stacked PRs (GA 2026-10-06) implement the same cascade over chained base branches; squash-merging the bottom PR duplicates the upper PR's diff until rebased. Revisit `stack` against the native surface if it grows powers deliver would otherwise hand-roll.
