# Publishing stays informational until someone bumps, then merge publishes

Publishing on every push to `main` was fine; failing a PR because the version wasn't bumped was not — it punished PRs that had no reason to ship yet. The PR-time `publish-preview` job now only comments (never fails) on whether this PR's published-file changes are already shipped, ready to ship, or waiting on a bump. Bumping happens on the PR itself, two ways into the same `bump` job: commenting `/bump` (default patch) or `/bump minor` / `/bump major` on a PR, or running the "CI" workflow manually from the Actions tab against that branch (`workflow_dispatch`, picking patch/minor/major from a dropdown) for anyone who prefers a button over typing a comment. Either path runs `scripts/bump.ts` and pushes the version bump straight to the target branch, so review and CI re-run against the real version that will ship. `publish` on push to `main` runs unconditionally but checks `scripts/should-publish.ts` first and skips quietly if that version is already on JSR, so an unbumped merge is a no-op, not a failure.
