# Publishing stays informational until someone bumps, then merge publishes

Publishing on every push to `main` was fine; failing a PR because the version wasn't bumped was not — it punished PRs that had no reason to ship yet. The PR-time `publish-preview` job now only comments (never fails) on whether this PR's published-file changes are already shipped, ready to ship, or waiting on a bump. Bumping happens on the PR itself: commenting `/bump` (default patch) or `/bump minor` / `/bump major` on a PR runs `scripts/bump.ts` and pushes the version bump straight to that PR's branch, so review and CI re-run against the real version that will ship. `publish` on push to `main` runs unconditionally but checks `scripts/should-publish.ts` first and skips quietly if that version is already on JSR, so an unbumped merge is a no-op, not a failure.
