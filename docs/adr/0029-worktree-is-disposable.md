# A Worktree is disposable; the Worker commits and ReadyRun verifies before removing it

The Worker commits its own work on the Ticket's Branch, told to by the package-owned prompt (ADR 0014), and ReadyRun treats exit 0 as success only when the Worktree is clean and the Branch's tree differs from the base it was cut from; otherwise the Run hard-stops. On success the Worktree is removed, because the Branch carries the work and the directory is only where a Worker ran. On a hard stop it is kept, so the failure is still there to look at. ReadyRun committing on the Worker's behalf was rejected: it would make the harness author a message describing code it did not write and `git add -A` a tree it does not understand. Accepting a clean tree alone as success was rejected because a Worker that did nothing also leaves a clean tree, and the Ticket would then leave the Frontier on the strength of an empty Branch — the silent lie ADR 0013 exists to prevent. Counting commits past the base was rejected because an empty commit is that same empty Branch wearing a commit, and a merge, cherry-pick, or reset onto something already reachable also satisfies a count without the Worker having written anything. Making disposal configurable was rejected: remove-on-success and keep-on-failure is right in both cases, so a `"remove" | "keep"` knob could only be set wrong, and a lifecycle callback would be the plugin system the v0 spec puts out of scope. The consequence to accept is that a genuinely no-op Ticket hard-stops rather than finishing cleanly, which we prefer, because "this was already done" is a call for a human rather than something an unattended loop concludes by producing nothing.

This decision was first written as 0027, colliding with the print-mode ADR that landed earlier the same day; issues #4, #62, #70 and #79 cite it under that number.
