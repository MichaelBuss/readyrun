# A Release PR is the only publish lever; every version ships to npm and JSR

Releases run through Changesets instead of the hand-rolled bump/comment machinery. Version intent lives inside each PR as a `.changeset/*.md` file — a bump kind plus a note that becomes the changelog entry — rather than version edits on a PR branch: two concurrent PRs both editing `jsr.json` conflict at merge time, and the loser's bump is computed against a stale base, which is exactly what small uniquely-named files avoid. `changesets/action` accumulates pending changesets into one **Version Packages PR** that bumps `package.json` and writes `CHANGELOG.md` (`@changesets/changelog-github` renders notes with PR and author links); `scripts/sync-version.ts` then drags `jsr.json` and `package-lock.json` to the same version, because the manifests' lockstep is an invariant, not a convention. Merging that PR is the only way a release happens: the same workflow then runs `scripts/release.ts`, which publishes npm via trusted publishing (OIDC through `id-token: write`, `--provenance`, no long-lived token) and JSR via OIDC as before, then tags `vX.Y.Z` and creates the GitHub Release from generated notes; every step checks what the registries already have, so a re-run after a partial failure and an ordinary docs-only merge to `main` both publish nothing and stay green. This overturns ADR 0020 — the bin-stripping objection died with direct npm, which puts `readyrun` on PATH for Consumers on Node ≥ 24 (type stripping), and both registries always receive the identical version — and supersedes ADR 0024, whose `/bump` comment and publish-preview guard are deleted: the informational spirit survives as the release-guidance PR comment, which reads the PR's changesets and nudges on missing `Closes #N` but never gates. npm publishing not being configured yet is a human step that fails instructively, with claim-scope / trusted-publishing / re-run instructions on the workflow summary and the merged PR, never a silent skip.

Human-only steps and the agent rules live in `docs/agents/release.md`, linked from `AGENTS.md`.
