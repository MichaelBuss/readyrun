# After Init the Launcher asks before assembling a Run

The Launcher's Init hand-off ended by walking straight into Run assembly, so a maintainer who typed bare `readyrun` only to write a config answered the tree, the cap, Permissions, model, Effort, and the base picker before the one confirm that could say "not now" — five answers to decline a Run. The hand-off now gates on one confirm ("Config created. Start a Run now?"), defaulted yes, because the command's purpose is a Run and Init was incidental; declining ends the process with exit 0 and an outro pointing at relaunching, since the Init succeeded and a failure exit would read as something to fix. Rejected: a "nothing right now" row inside the tree multi-select — it muddies the rendering's one semantic (a pick names the explicit list, the top choice names the rootless **Frontier**, and `required` keeps an empty submit from reading as "take everything"), and the tree question is where a declined waiting confirm re-asks, which a nothing-row would poison; and a gate before Init completes, which would be a question about a **Run** on a config that may never exist. The gate collects nothing flag-expressible — it decides whether assembly starts at all, the same shape as the "Run init?" confirm that opened the hand-off — and lives only in the Init path: with a config already present, the Launcher is unchanged.
